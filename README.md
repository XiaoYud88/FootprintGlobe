# 足迹地球 · FootprintGlobe

一个只给自己用的 iPhone App：打开就是一颗**自绘的 3D 地球**，用定位自动记录你去过的城市，去过的国家 → 省份 → 城市会随缩放逐级亮起来。

- 纯 SwiftUI，**零第三方地图 SDK**，不需要任何 API Key，不需要联网
- 范围：**中国大陆（34 省 / 370 市）+ 日本（47 都道府县）+ 南极洲 + 北极**，边界数据打包在 App 内
- 最小单位是**地级市**（太原市、秦皇岛市……）
- 定位数据只在本机计算，不上传、不要账号

当前版本：**M1-V2（0.4.0）**

## 一、这一版做了什么（M1-V2）

### 1.1 天空重做：从「一堆白点」到有层次的天

| 之前 | 现在 |
| --- | --- |
| 150 个随机白点，一动不动 | **三层星**（170 暗小 / 70 中 / 20 亮）：亮度、半径、闪烁幅度各不相同，只有中暗两层呼吸，亮星不闪，才不会像坏掉的灯 |
| 没有背景 | 深空渐变（顶部偏蓝紫 → 底部近黑）+ 两团糊掉的星云（紫 / 青）+ **银河**：三条嵌套椭圆旋转 −26°，叠起来像一条斜着的光带 |
| 没有月亮 | **月亮**：三层光晕 + 六块环形山 + 相位阴影。相位按真实朔望月（29.53 天）算，今天是残月就画残月 |
| 拖动地球星空不动 | 星星按**相机经度视差**横向漂移，转地球的时候天空也有反应 |

实现：`UI/SkyView.swift`，`Canvas` + `TimelineView(by: 1.6s)`；星星编号用固定种子的 LCG，所以每次打开星图都一样（不会每次重开就换一片天）。

### 1.2 地球重画：让球看起来是「被太阳照着的」

| 能力 | 实现方式 |
| --- | --- |
| **晨昏线** | 每 60 秒算一次**太阳直射点**（赤纬 + 时差，`Core/SolarPosition.swift`），在球面上以直射点为圆心铺一层由透明到黑的径向渐变——正对太阳的一侧亮、背面暗，交界处自然形成晨昏线，不需要逐像素光照 |
| **暖色晨昏带** | 渐变最外圈叠一条橙色带（黎明 / 黄昏的颜色），比一刀切的黑边真实得多 |
| **海洋渐变 + 双层大气** | 球面从顶部深蓝到底部近黑（浅色主题是米白到浅灰）；外边两圈模糊光晕：外圈散、内圈紧，像真有大气的散射 |
| **描边** | 白色细边 + 蓝色外发光，球和星空之间有明确的边界 |

数学上的巧处：球面上距离球心 `d` 的点，与太阳方向的夹角 `θ` 满足 `d = R·sinθ`，而亮度就是 `cosθ = √(1−(d/R)²)`。所以「以直射点为圆心的径向渐变」本身就是正确的光照分布，渐变的每一档 stop 只是这个函数的采样。

### 1.3 数据安全：zip 备份 / 恢复

| 能力 | 实现方式 |
| --- | --- |
| **备份** | `设置 → 备份与恢复 → 立即备份`，打出一个普通 zip：`footprint.json`（全部记录 / 备注 / 标签 / 星级 / 待确认）+ `photos/*`（所有照片）+ `manifest.json`（版本、时间、条数）。落在沙盒 `Documents/Backups/`，最近 5 份自动保留 |
| **导出** | 备份完成后出现 `导出刚做好的备份`，走系统分享面板 → 存「文件」、隔空投送、发给自己都行。开启文件共享后，也能在「文件 → 我的 iPhone → 足迹地球」里直接看到 |
| **恢复** | `从文件恢复…` 选 zip，先**读出包里有什么**（多少城市 / 照片 / 多大 / 哪天打的），确认弹窗说清楚要覆盖当前多少条记录，按下去才真正写 |
| **兼容性** | 读的时候同时支持「存储」和「deflate」两种压缩，所以用系统「压缩」功能自己做出来的 zip 也能恢复；`footprint.json` 放在子目录里也认 |
| **不引第三方** | `Core/ZipArchive.swift` 是手写的（写：不压缩；读：`compression_decode_buffer`），备份功能不能因为某个包升级失效 |

> 为什么会想做这个：这个 App 没有账号、没有云，数据只在这台手机上。换机、重装、误点「清空所有记录」之后，唯一能救回来的就是一个自己能拿在手里的文件。

### 1.4 回忆：足迹海报导出

护照页左上角的分享按钮 → 渲染一张 1080×N 的 PNG 海报：

- 顶部：称号（大地行者之类）+「自 2015 年起 · 37 座城市 · 12 个省级」
- 中间：**同一颗地球**（同一个 `GlobeView`、同一套边界数据），视角自动对准「去过的地方的重心」
- 下面：城市 / 省级 / 故事 / 照片四个数字、四极（最北 / 最南 / 最东 / 最西）、面积覆盖率条、徽章进度
- 底部：版本 + 生成日期

用 `ImageRenderer` 以 3 倍渲染（不是截屏），所以放大看文字边缘是干净的；可以「存到相册」或直接分享。

### 1.5 手感

| 改动 | 效果 |
| --- | --- |
| **启动推近** | 进 App 时地球从远处（缩得比正常小 40%）用 1.35 s 缓出推到位，像镜头靠近，而不是「啪」一下出现 |
| **缩放阻尼** | 双指继续往外捏会越来越沉（越界量只走 32%），不会突然卡死也不会无限漂 |
| **松手回弹** | 停在越界位置时用 spring（0.34 s）弹回合法区间，和系统的手感一致 |
| 半径曲线 | 地球半径随缩放取 `0.34 + 0.20 · z`，缩到最小也留得住球体，不会缩成一个点 |

### M0-V2 修复的那个 BUG（留个记录）

**现象：** 缩放到中国，地球消失了，中国也没出现。

**根因：** 世界坐标存的是 `y = -lat`（数据 y 轴朝下），而 `ChinaMapView` 的 `CGAffineTransform` 又写了 `d: -ky`，等于把纬度翻转了两次。结果整张中国地图被推到屏幕外 —— 北京算出来的 y 是 985，而屏幕高只有 852。

**修法：** 把投影逻辑抽成 `Core/ChinaProjection.swift`，符号改正为 `d: +ky`，并让「屏幕点 ↔ 经纬度」双向可逆。

### 界面为什么会越来越多组件也不乱

`Theme.swift` 里是设计令牌层 `Theme.Layout`（页面留白 18 / 卡片圆角 18 / 控件高 40 / 浮动间距 10 / 每城照片 3 张……）和 `Theme.Typo`（title / subtitle / label / body / caption / number / bigNumber）。主界面按槽位划分：

```
header      标题 + N/419 城市 · N 省 · N 段故事（点进度环进清单）
zoomRail    右侧上下 +/− 与当前层级（地球 / 国家 / 省份 / 城市）
bottomStack 当前城市 chip → 权限提示卡（可关）→ 底部 dock
toastLayer  轻提示
celebration 点亮动画（全屏浮层）
```

新组件只占一个新槽位，间距和字阶都从令牌取。记录面板 `CityRecordSheet` 由卡片拼成（状态 / 时间 / 故事 / 照片 / 标签 / 星级 / 删除），护照页 `PassportView` 也是卡片拼的。

### 关键设计

**为什么能不用地图 SDK？** 因为只需要两个国家 + 两极的行政边界。数据是离线的（边界 2.8 MB + 世界底图 186 KB），投影是在 `Canvas` 里自己算的，所以既没有配额、也没有网络依赖。

**坐标系。** 中国边界来自 DataV GeoAtlas，是 **GCJ-02**；iOS 的 `CLLocation` 是 **WGS-84**。所以在定位入口用 `GeoMath.wgs84ToGcj02` 转换一次，之后全链路都用 GCJ-02。日本 / 南极来自 Natural Earth 系数据，本就是 WGS-84，**不参与中国那套纠偏**，只在绘制时直接用。

**北极怎么来的？** 北极没有陆地、没有行政边界，也不可能有人长期停留。为了让「极北」这件事能被记录，加载边界时**合成**了一个很小的极区圆帽（覆盖极点附近，code `AR` / 城市 `AR-POLE`，中心 15°E 88°N）：能画、能点、能手填，但不参与定位判定和面积占比。

**为什么不需要定时轮询？** iOS 不允许后台定时采样。这里用的是 `startMonitoringSignificantLocationChanges()`（显著位移被动唤醒，几乎不耗电）+ 前台 `requestLocation()`。系统没唤醒时，候选会留在「待确认」里让人手动确认。

**防误记的判定（`VisitTracker`）**

```
进城            → 只生成候选（不写记录）
候选            → sampleCount >= 2 且 spanHours >= 3   ⇒ 转正
离开时还没达标  → 丢弃（这就是高铁经过进不了名单的原因）
高速 + 停留极短 → 直接判为路过
已在名单再进城  → 只更新 lastSeen / sampleCount / 天数
```

停留阈值（2/3/4/6 小时）和最少采样次数（2–5 次）都能在设置里改。

## 三、怎么跑起来

环境：macOS + **Xcode 16 或更新**（iOS 17+ 真机 / 模拟器）。

1. 打开 `FootprintGlobe.xcodeproj`
2. 选中 `FootprintGlobe` target → **Signing & Capabilities**
   - 勾选 `Automatically manage signing`
   - `Team` 选你自己的 Apple ID（免费账号即可）
   - 如果 `Bundle Identifier` 冲突，把 `com.personal.footprintglobe` 改成任意唯一值
3. 手机连上电脑，选自己的设备，⌘R 运行
4. 首次启动按提示给定位权限：**使用 App 期间** + **始终允许**（后台补点必需）；第一次加照片时会问相册权限

> 用免费开发者账号签的 App，**7 天后会失效**，重新 ⌘R 一次即可；证书过期后桌面图标点开会闪退，属正常现象。

处理流程：只保留外环 → Douglas–Peucker 简化（省 0.006°、市 0.004°）→ 丢弃跨度 < 0.035° 的碎岛 → 合并成单个 `boundaries.json`。加载耗时约 90 ms，一次性在启动时完成。

面积用球面多边形梯形积分算（不是平面近似），所以「已点亮面积 / 可点亮面积」可以横跨不同纬度比较。

## 五、隐私

- 定位坐标只在本机做多边形判定，**不上传、不落第三方**
- 照片只写在本机沙盒里（`Application Support/FootprintGlobe/photos/`），**不压缩上传、不生成缩略图联网**
- 没有账号、没有埋点、没有网络请求（App 本身不需要联网）
- 所有记录保存在沙盒内，卸载 App 即彻底删除

## 七、怎么验收这一版（M1-V2）

按顺序走一遍，10 分钟能看完：

1. **星空和月亮** —— 用深色主题启动。应该看到深空渐变 + 一团紫 / 一团青的星云 + 一条斜着的银河带 + 三层亮度不同的星星，**右上方有一轮带环形山的月亮**。等 2 秒能看到星星在轻微呼吸。
2. **月相是真的** —— 月亮有一侧是暗的。查一下今天的月相（比如农历初七是上弦），暗面方向应该对得上。
3. **启动推近** —— 杀掉 App 重开：地球应该从远端缓出推到位（约 1.3 秒），不是直接出现。
4. **晨昏线** —— 看球面：正对太阳的一侧亮、另一侧暗，交界处有一条偏橙的暖色带。等几分钟（或改手机时间）再看，暗区会移动。中国的白天黑夜应该和现实一致。
5. **缩放阻尼** —— 双指用力往外捏，捏到最小之后会明显「沉」下去，松手弹回原位，不会卡死也不会缩成一个点。
6. **备份** —— `设置 → 备份与恢复 → 立即备份`。应该出现一行「足迹地球-备份-日期.zip」+ 文件大小，下面多出「导出刚做好的备份」。点导出，能存到「文件」或隔空投送。
7. **恢复** —— 先记下当前城市数，然后 `设置 → 数据 → 清空所有记录`（会全空）。再 `备份与恢复 → 从文件恢复…`，选刚备份的 zip：确认弹窗里应该写着「包里是 N 个城市 · M 张照片 · X KB」，点「覆盖恢复」，记录和照片都回来。
8. **包是普通 zip** —— 把导出的 zip 用电脑解开，应该能直接看到 `footprint.json` 和 `photos/` 目录，用任何解压软件都能打开。
9. **海报** —— 护照页左上角分享按钮。应该弹出一张海报：称号、地球（视角对着你去过的地方）、四个数字、四极、覆盖率条、徽章进度。点「存到相册」能在相册里找到，点「分享」能发出去。
10. **海报清晰度** —— 把海报放大到最大，文字边缘应该是干净的（3 倍渲染，不是截屏）。
11. **老数据不丢** —— 从 0.3.0 升级上来，之前的城市、时间、故事、标签、照片应该原样还在。

已知限制：台湾省数据源只有省级轮廓，暂按一个整块显示；日本只有都道府县级（没有市町村）；北极是合成区域，不能靠定位自动记录，只能手填；长时间静止系统可能不唤醒，靠「待确认」兜底；还没有 iCloud / 跨设备自动同步（这一版只做到手动 zip 备份）。
